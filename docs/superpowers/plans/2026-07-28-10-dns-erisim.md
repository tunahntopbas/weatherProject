# DNS Erişimi (Local + Global) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `06-kubernetes-rancher.md`'de `192.168.56.11:30080` gibi çıplak bir IP:port üzerinden erişilen uygulamaya (1) yerel ağda bir isimle (`weather.local`) ve (2) dünyanın herhangi bir yerinden bir alan adıyla (`weather.<alan-adin>`) erişilebilmesini sağlamak.

**Architecture:** İki farklı DNS mekanizması, iki farklı problemi çözer. **Local DNS**: host makinenin `hosts` dosyasına bir satır ekleyerek `weather.local` ismini doğrudan `node1`'in IP'sine eşlemek — sadece bu makine bu ismi tanır. **Global DNS**: ev/okul ağının arkasında, genelde herkese açık (public) bir IP'si olmayan bir Kubernetes cluster'ını internete açmak için router'da port yönlendirmesi yapmak yerine **Cloudflare Tunnel** kullanılır — cluster içinde çalışan bir `cloudflared` pod'u, Cloudflare'e **dışa doğru** bir bağlantı açar (gelen bağlantı beklemez), bu sayede hiçbir router ayarına dokunmadan ve ev ağını dışarıya açmadan genel internetten erişim sağlanır.

**Tech Stack:** Windows `hosts` dosyası, Cloudflare Tunnel (`cloudflared`), Kubernetes Secret/Deployment.

## Global Constraints

- Bu plan, sahibi olduğun (veya Cloudflare'e ekleyebileceğin) bir alan adının (`<alan-adin.com>`) var olduğunu varsayar — global DNS bir alan adı olmadan kurulamaz
- Tunnel token'ı **asla** Git'e commit edilmeyecek, Kubernetes Secret olarak imperative oluşturulacak
- Router'da port yönlendirmesi (port forwarding) **bilerek yapılmıyor** — bu, ev ağını doğrudan internete açar ve genellikle çoğu ev interneti sağlayıcısında (CGNAT nedeniyle) zaten çalışmaz; Cloudflare Tunnel bu riski almadan aynı sonucu verir

### Task 1: Local DNS — `weather.local` ile erişim

**Files:** Yok (Windows sistem dosyası düzenlenir, repo'ya dahil değil)

**Interfaces:**
- Consumes: `node1` IP'si (`192.168.56.11`, bkz. `05-virtualbox-ubuntu-vm.md`), `frontend` NodePort'u (`30080`, bkz. `06-kubernetes-rancher.md` Task 7)
- Produces: host makineden `http://weather.local:30080` ile erişim

- [ ] **Step 1: hosts dosyasını yönetici olarak düzenle**

PowerShell'i **yönetici olarak** aç:

```powershell
Add-Content -Path "$env:SystemRoot\System32\drivers\etc\hosts" -Value "`n192.168.56.11 weather.local"
```

- [ ] **Step 2: Doğrula**

```powershell
ping weather.local
```

Expected: `192.168.56.11` adresinden cevap gelir (Kubernetes NodePort ICMP'e cevap vermeyebilir, önemli olan `Pinging weather.local [192.168.56.11]` satırının doğru IP'yi göstermesi; `Request timed out` görünse de IP çözümlemesi doğruysa DNS kısmı çalışıyor demektir).

```powershell
curl http://weather.local:30080/
```

Expected: HTTP 200, frontend HTML'i döner — artık IP ezberlemeden isimle erişiliyor.

**Not:** Bu eşleme sadece **bu makinede** çalışır. Ağdaki başka bir bilgisayardan `weather.local` çözülmez — bunun için ağ genelinde bir DNS sunucusu (örn. router'ın DNS ayarları veya `dnsmasq`) gerekir; bu, bu planın kapsamı dışında bir sonraki öğrenme adımıdır.

### Task 2: Cloudflare Tunnel oluştur ve token al

**Files:** Yok

**Interfaces:**
- Consumes: Cloudflare hesabı + Cloudflare'e eklenmiş bir alan adı (`<alan-adin.com>`)
- Produces: bir tunnel token (Task 3'te Kubernetes Secret olarak kullanılacak)

- [ ] **Step 1: Cloudflare Zero Trust dashboard'a git**

https://one.dash.cloudflare.com adresine git (Cloudflare hesabınla giriş yaptıktan sonra). Sol menüden Networks > Tunnels.

- [ ] **Step 2: Yeni tunnel oluştur**

"Create a tunnel" > Connector type: `Cloudflared` > isim: `weatherproject-tunnel` > "Save tunnel".

- [ ] **Step 3: Tunnel token'ını kopyala**

Kurulum ekranında Docker/Kubernetes komutu içinde bir `--token eyJ...` değeri gösterilir. Bu token'ın sadece `eyJ...` kısmını (tırnak işaretleri hariç) kopyala ve güvenli bir yere geçici olarak kaydet (Task 3'te kullanılacak, sonra silinebilir).

**Neden bu token hassas:** Bu token, senin tunnel'ına bağlanma ve trafiği yönlendirme yetkisi verir — bir şifre gibi davranılmalı, asla Git'e veya herkese açık bir yere yazılmamalı.

### Task 3: cloudflared'i cluster içinde çalıştır

**Files:**
- Create: `k8s/cloudflared-deployment.yaml`

**Interfaces:**
- Consumes: Task 2'deki tunnel token, `weatherproject-cluster` (bkz. `06-kubernetes-rancher.md`)
- Produces: cluster içinde çalışan, Cloudflare'e dışa doğru bağlı bir `cloudflared` pod'u. Task 4'teki Cloudflare public hostname yapılandırması bu tunnel'ı hedefleyecek.

**Neden pod cluster içinde (host makinede değil):** `cloudflared`'ı cluster'ın **içinde** çalıştırmak, Cloudflare'den gelen trafiğin doğrudan Kubernetes'in kendi iç ağı üzerinden (`frontend.weatherproject.svc.cluster.local`) `frontend` Service'ine ulaşmasını sağlar — ne `NodePort`'a ne de host makineye bağımlı kalınır. Host makine kapansa bile (cluster ayaktaysa) tunnel çalışmaya devam eder.

- [ ] **Step 1: Tunnel token'ını Kubernetes Secret olarak oluştur**

```powershell
kubectl create secret generic cloudflared-secret `
  --namespace weatherproject `
  --from-literal=tunnel-token='<task-2-deki-token>'
```

- [ ] **Step 2: Deployment manifest'ini yaz**

```yaml
# k8s/cloudflared-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: cloudflared
  namespace: weatherproject
spec:
  replicas: 1
  selector:
    matchLabels:
      app: cloudflared
  template:
    metadata:
      labels:
        app: cloudflared
    spec:
      containers:
        - name: cloudflared
          image: cloudflare/cloudflared:2024.8.3
          args:
            - tunnel
            - --no-autoupdate
            - run
          env:
            - name: TUNNEL_TOKEN
              valueFrom:
                secretKeyRef:
                  name: cloudflared-secret
                  key: tunnel-token
```

- [ ] **Step 3: Uygula ve doğrula**

```powershell
kubectl apply -f k8s/cloudflared-deployment.yaml
kubectl get pods -n weatherproject -l app=cloudflared
kubectl logs -n weatherproject -l app=cloudflared --tail=20
```

Expected: pod `Running`, loglarda `Registered tunnel connection` benzeri bir satır (bağlantının Cloudflare'e başarıyla kurulduğunun kanıtı).

Cloudflare Zero Trust dashboard'da Networks > Tunnels ekranına dön.

Expected: `weatherproject-tunnel` artık `Healthy` (yeşil) durumda görünür.

- [ ] **Step 4: Commit**

```bash
git add k8s/cloudflared-deployment.yaml
git commit -m "feat(dns): cloudflared tunnel connector deployment"
```

### Task 4: Public hostname yapılandır ve dışarıdan doğrula

**Files:** Yok (Cloudflare dashboard üzerinden)

**Interfaces:**
- Consumes: `weatherproject-tunnel` (Task 3), `frontend` Service (bkz. `06-kubernetes-rancher.md` Task 7)
- Produces: `https://weather.<alan-adin.com>` üzerinden dünyanın herhangi bir yerinden erişilebilen uygulama

- [ ] **Step 1: Public hostname ekle**

Cloudflare Zero Trust > Networks > Tunnels > `weatherproject-tunnel` > Public Hostname sekmesi > "Add a public hostname":
- Subdomain: `weather`
- Domain: `<alan-adin.com>` (dropdown'dan seç)
- Type: `HTTP`
- URL: `frontend.weatherproject.svc.cluster.local:80`

Kaydet.

**Neden `HTTP` (HTTPS değil):** `cloudflared` cluster içinde `frontend` Service'ine düz HTTP ile bağlanıyor (aynı cluster içi güvenli ağ üzerinden), ama Cloudflare **dışarıya** karşı bu bağlantıyı otomatik olarak HTTPS'e çevirir (Cloudflare'in kendi TLS sertifikası ile). Yani kullanıcı tarayıcısından her zaman `https://` görür, iç bağlantı ise basit tutulur.

- [ ] **Step 2: DNS kaydının oluştuğunu doğrula**

Cloudflare dashboard > DNS > Records.

Expected: `weather` isimli bir `CNAME` kaydı, hedefi tunnel'ın ID'sine ait `.cfargotunnel.com` adresi, otomatik olarak eklenmiş görünür (Cloudflare bunu Step 1'de senin için oluşturur).

- [ ] **Step 3: Farklı bir ağdan (ev ağının dışından) test et**

Telefonunun Wi-Fi'ını kapatıp mobil veriyle (ev ağı dışında bir ağ) tarayıcıdan `https://weather.<alan-adin.com>` adresine git.

Expected: HTTPS kilit simgesiyle uygulama arayüzü açılır, bir şehir arayıp hava durumu sonucu görebiliyorsun — bu istek sırasıyla: telefon -> Cloudflare -> tunnel -> cluster içi `frontend` Service -> `backend` -> Redis/PostgreSQL/OpenWeatherMap zincirinden geçer.

- [ ] **Step 4: Uçtan uca özet doğrulama**

Bu adımda tüm 10 planın birlikte çalıştığını doğrula:

```powershell
curl http://weather.local:30080/api/weather/Istanbul          # Task 1: local DNS
curl https://weather.<alan-adin.com>/api/weather/Istanbul     # Task 4: global DNS
```

Expected: her ikisi de aynı JSON hava durumu cevabını döner — aynı backend'e, iki farklı yoldan (yerel isim / genel internet) ulaşılabiliyor.
